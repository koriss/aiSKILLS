# Release notes — v19.2.1 (Honesty Hardening)

## Summary

v19.2.1 closes the policy-vacuum observed in `RUN-36a7dcf7afd7`: the runtime can
no longer silently execute from backup skill directories, no longer accepts
unsafe `/tmp` runs roots without explicit consent, and no longer emits ambiguous
stub delivery when Telegram routing data is missing.

## Operator-visible changes

- **Canonical path guard** — entrypoints refuse non-canonical skill roots
  (including `*.bak*`, `*.old*`, `*.backup*`, `*.disabled*`, `copy of *`) with
  `RFO-NON-CANONICAL-SKILL-PATH` (exit `11`).
- **Runs-root guard** — `--runs-root` under `/tmp` is denied by default with
  `RFO-RUNS-ROOT-FORBIDDEN` (exit `12`), allowed only with
  `RFO_ALLOW_TMP_RUNS_ROOT=1` for smoke usage.
- **Telegram delivery truth path** — `chat_id` resolution now follows strict
  order: `request -> argv -> env(consent) -> fail`; missing routing data produces
  `delivery_not_proven` with explicit reasons instead of silent `stub_only`.
- **Verifier extensions** — `verify_openclaw_run.py` adds:
  `LIE-DETECTED-WRONG-SKILL-PATH`,
  `LIE-DETECTED-WRONG-RUNS-ROOT`,
  `LIE-DETECTED-DELIVERY-STUB-WITHOUT-CONSENT`,
  `LIE-DETECTED-NARRATIVE-WITHOUT-EVIDENCE`.
- **Smoke + repro wrappers** — added replayable v19.2.1 wrappers:
  `_smoke_v19_2_1_honesty.py`, `_smoke_v19_2_1_repro_baseline.py`,
  `_smoke_v19_2_1_repro_after_fix.py`.

## Migration

- `TELEGRAM_API_BASE` must be available in the runtime environment.
- Production invocation must pass `--chat-id` and `--reply-to-message-id` from
  the incoming Telegram update.
- `TELEGRAM_CHAT_ID` environment fallback is smoke-only (`RFO_ALLOW_ENV_CHAT_ID=1`).
