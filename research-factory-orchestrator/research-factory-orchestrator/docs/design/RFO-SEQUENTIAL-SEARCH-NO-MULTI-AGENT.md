# RFO: последовательный поиск, без «мультиагентного» оркестратора

## Продуктовое правило

- **RFO не является swarm из нескольких автономных агентов**, которые дебатируют или параллельно планируют исследование.
- **Поиск и загрузка источников выполняются последовательно** в одном процессе моста: сначала серия запросов к JSON relay (если включён фан-аут шаблонов), затем обход URL для извлечения текста — без пула потоков/процессов и без `asyncio`-параллели в relay-пути.

## Что означает «fanout» здесь

Историческое имя **fanout** = **несколько вариантов поисковой строки** из `contracts/query-fanout-config.json`, выполняемых **один за другим** в стабильном порядке; результаты **сливаются и дедуплицируются по URL** в `scripts/rfo_query_fanout.py`. Это **расширение покрытия запросами**, а не параллельные субагенты.

Ограничить число таких строк можно переменной окружения **`RFO_QUERY_FANOUT_QUERIES`** (верхняя граница числа шаблонов; см. `build_query_vectors` в `scripts/rfo_query_fanout.py`). Значение **`1`** даёт по сути один запрос вида `{task}` (первый шаблон в конфиге).

## Где не путать с multi-agent

- **Верификационные** каналы (советы ADR по blinded checker / advisory «совету» моделей) — отдельный контур **оценки**, не второй автономный исследователь в проде.
- **Plain subagent** в хосте — анти-паттерн для slash RFO (см. `SKILL.md`): это **не** часть пайплайна RFO.
