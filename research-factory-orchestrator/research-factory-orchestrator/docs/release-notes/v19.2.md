# Release notes — v19.2.0 (Runtime Truth Restoration)

> **Current tree:** Telegram adapters, `tools/agent_telegram/`, and Telegram-specific
> release smokes are **removed**; delivery is host-owned. The bullets below describe
> the original v19.2.0 shipment.

## Summary

v19.2.0 closes the **runtime ↔ validator** gap: artifacts emitted during `cmd_run`
match what V1–V6 gates consume, work units execute with evidence, collection/coverage
flags are truthful. At release time, optional Telegram delivery could be exercised
with a **mock Bot API** trace (since removed from this repo).

- **Dual layout + PKG_REQUIRED mirrors** — root `sources.json` / collection results
  are first-class (`runtime/util.py`, `runtime/compatibility-matrix.json`).
- **Telegram (historical)** — v19.2.0 briefly shipped `providers/telegram/` and
  `tools/agent_telegram/` (ADR-014); superseded by compute-only handoff (ADR-015).
- **Release gates (historical)** — older transcripts may list `_smoke_telegram_*`;
  current `REQUIRED_GATES` are defined in `scripts/validate_release.py` as updated.
- **Honesty harness** — `scripts/verify_openclaw_run.py` for loop testing under
  unreliable LLM narration (ADR-015).
